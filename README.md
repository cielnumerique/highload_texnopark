# Проектирование видеостримингового сервиса

## 1. Тема и целевая аудитория

**Тип:** видеостриминговый сервис на примере Netflix.

**Аудитория:** пользователи по всему миру. Для проекта принимаем MAU = 315 млн и DAU = 189 млн. Ориентир — 301,63 млн платных подписок Netflix в Q4 2024 [1]. Подписки и активные пользователи — разные метрики; MAU и DAU здесь являются допущениями.

**MVP:**

- Регистрация и авторизация.
- Главная страница с рекомендациями.
- Поиск и карточки фильмов и сериалов.
- Просмотр видео с выбором качества.
- «Мой список».
- Оценки.
- Чтение, написание, изменение и удаление отзывов на фильмы.

Рекомендации учитывают историю и оценки. Видео раздаётся через CDN; качество меняется по скорости соединения. Оценки и отзывы доступны после просмотра. На фильм разрешён один отзыв от пользователя; выдача — страницами по 10 записей.

## 2. Расчёт нагрузки

### 2.1. Продуктовые метрики и RPS

| Метрика | Значение |
|---|---:|
| MAU | 315 млн |
| DAU/MAU, допущение | 0,6 |
| DAU | 315 млн × 0,6 = 189 млн |
| Рост аудитории за год, допущение по росту подписок Netflix [1][2] | 15,9% |

Частоты действий принимаются для модели. Средний RPS = `DAU × действий в сутки / 86 400`; пиковый — средний ×3. RPS округлён. Регистрации рассчитаны по приросту аудитории без оттока: около 50,1 млн в год.

| Действие | На DAU в сутки | Средний RPS | Пиковый RPS |
|---|---:|---:|---:|
| Регистрация | — | 1,6 | 5 |
| Авторизация | 2 | 4 400 | 13 200 |
| Главная / рекомендации | 3 | 6 600 | 19 800 |
| Поиск | 1,5 | 3 300 | 9 900 |
| Карточка тайтла | 5 | 10 900 | 32 700 |
| Запуск просмотра | 3 | 6 600 | 19 800 |
| «Мой список» | 0,4 | 900 | 2 700 |
| Оценка | 0,3 | 700 | 2 100 |
| Страница отзывов | 1 | 2 200 | 6 600 |
| Создание, правка или удаление отзыва | 0,01 | 22 | 66 |
| **Всего API** | | **35 623,6** | **106 871** |

### 2.2. Хранение данных

Для обычной записи принимаем 300 байт. Отзыв — 1 300 байт: 500 символов × 2 байта и 300 байт служебных полей.

| Данные | Записей на существующий аккаунт | Объём |
|---|---:|---:|
| Профиль | 1 | 0,3 КБ |
| «Мой список» | 25 | 7,5 КБ |
| История просмотров | 300 | 90 КБ |
| Оценки | 60 | 18 КБ |
| Отзывы | 3 | 3,9 КБ |
| **Всего** | **389** | **119,7 КБ** |

Для каталога принимаем 10 000 тайтлов: 45% фильмов и 55% сериалов, по 25 эпизодов. Фильм длится 110 минут, эпизод — 48 минут. Получаем 142 000 видеоединиц и 118 250 часов контента.

Все версии качества занимают `0,3 + 1 + 3 + 7 = 11,3 ГБ/час`; мастер-копия — 80 ГБ/час; метаданные и изображения — 100 МБ/тайтл. Размеры приняты для модели хранения.

| Данные | Количество | Объём, ТБ |
|---|---|---:|
| Видео для раздачи | 142 000 видеоединиц | 1 336,23 |
| Мастер-копии | 142 000 видеоединиц | 9 460 |
| Метаданные и изображения | 10 000 тайтлов | 1 |
| Профили, история, избранное и оценки | 315 млн аккаунтов | 36,48 |
| Отзывы | 945 млн записей | 1,23 |
| **Всего** | | **10 834,93** |

Объёмы указаны без индексов, журналов и реплик. Итоги рассчитаны до округления; 1 ГБ = 10⁹ байт, 1 ТБ = 10¹² байт.

### 2.3. Прирост данных

Новый аккаунт содержит только профиль. Остальные данные появляются при действиях DAU. История создаёт запись при первом запуске видео. Для запаса считаем все просмотры, оценки и отзывы новыми, а операции со списком — добавлениями. Повторы и удаления уменьшают фактический прирост.

| Данные | Новых записей на DAU в сутки, до | Байт на запись | Прирост, ГБ/сутки |
|---|---:|---:|---:|
| История просмотров | 3 | 300 | 170,10 |
| Оценки | 0,3 | 300 | 17,01 |
| «Мой список» | 0,4 | 300 | 22,68 |
| Отзывы | 0,01 | 1 300 | 2,457 |
| **Всего** | **3,71** | | **212,247** |

Прирост на одного DAU: `3,7 × 300 + 0,01 × 1 300 = 1 123 байта/сутки`.

При линейном росте аудитории на 15,9% средний DAU за год: `189 млн × (1 + 0,159 / 2) = 204 025 500`. Новые профили: `315 млн × 15,9% ≈ 50,1 млн`. Их дальнейшая активность уже учтена в DAU.

Годовой прирост пользовательских данных: `(204 025 500 × 1 123 × 365 + 50,1 млн × 300) / 10¹² ≈ 83,64 ТБ`.

Принимаем 600 новых тайтлов в год: 270 фильмов и 330 сериалов. Прирост видео: `270 × 110 / 60 + 330 × 25 × 48 / 60 = 7 095 часов`.

| Данные | Расчёт | Прирост, ТБ/год |
|---|---|---:|
| Версии для раздачи | 7 095 ч × 11,3 ГБ/ч | 80,17 |
| Мастер-копии | 7 095 ч × 80 ГБ/ч | 567,60 |
| Метаданные и изображения | 600 × 100 МБ | 0,06 |
| Пользовательские данные, включая отзывы | Активность DAU и новые профили | 83,64 |
| **Всего** | До округления строк | **731,48** |

## 3. Глобальная балансировка нагрузки

### 3.1. Группы трафика

| Группа | Условный домен | Назначение |
|---|---|---|
| API | `api.stream.example` | Действия пользователя; важен быстрый ответ |
| Видео | `video.stream.example` | Большие файлы, повторные загрузки; раздача через CDN |
| Статика | `static.stream.example` | Постеры, JS и CSS; отдельные правила кеширования |

### 3.2. Размещение и нагрузка

Используем четыре региона AWS, чтобы обслуживать аудиторию в разных частях мира [3]. Доли подписок Netflix принимаем за доли запросов [1]. Для каждого метода: `RPS региона = пиковый RPS метода × доля региона`.

| Площадка | Аудитория | Доля | Пик API, RPS | Мощность с резервом, RPS |
|---|---|---:|---:|---:|
| NA — Вирджиния | США и Канада | 29,7% | ≈ 31 741 | ≥ 81 051 |
| EU — Франкфурт | Европа, Ближний Восток, Африка | 33,5% | ≈ 35 802 | ≥ 81 051 |
| SA — Сан-Паулу | Латинская Америка | 17,7% | ≈ 18 916 | ≥ 22 700 |
| AP — Сингапур | Азиатско-Тихоокеанский регион | 19,1% | ≈ 20 412 | ≥ 24 495 |

Вирджиния выбрана как площадка на востоке США с инфраструктурой Ашберна [4]; Франкфурт — в континентальной Европе с узлом DE-CIX [5]; Сан-Паулу — в Бразилии с IX.br [6]; Сингапур — в Юго-Восточной Азии. Это начальный выбор: преимущество перед другими городами требует проверки задержек и аудитории по странам.

В Африке предусмотрена доставка через CDN в Южной Африке [7], API пока работает во Франкфурте. Необходимость отдельного API-региона требует проверки задержек.

### 3.3. Порядок балансировки

Для глобального выбора региона API используем **GeoDNS**: он позволяет явно задать направления по географии [8]. Порядок обращения, если готового DNS-ответа нет в кеше:

1. **DNS-запрос** через резолвер пользователя доходит до DNS-провайдера. Anycast позволяет обслуживать IP его DNS-сервера из нескольких точек; маршрут выбирается с участием BGP [9]. Это выбор узла DNS.
2. **GeoDNS** возвращает IP регионального балансировщика по географии DNS-запроса. Это выбор региона API.
3. **Локальный балансировщик** принимает соединение клиента и выбирает работающий сервер приложения в регионе.
4. **Видео** плеер получает напрямую из CDN по подписанной ссылке от API [10][11]. При ошибке используется резервный CDN-пул.

**Отказ региона:** NA → EU, EU → NA, SA → NA, AP → EU. Проверки доступности связаны с правилами переключения на резерв. При перегрузке мониторинг должен менять распределение новых DNS-ответов; сама географическая политика нагрузку не измеряет. Из-за DNS-кеша переключение не мгновенное: клиенту нужен заранее известный резервный адрес для переподключения [12].

Резерв рассчитан на отказ одного региона и ещё 20% запаса: для NA и EU `106 871 × 0,632 × 1,2 ≈ 81 051 RPS`. Сервисы и данные должны быть готовы заранее. История реплицируется асинхронно: после аварии последние изменения могут быть недоступны.
